# AGENTS.md

Guidance for working in this repository.

## What this is

- Personal blog **The Knowledge Mart** (Data Engineering), built with the **Chirpy** Jekyll theme (`jekyll-theme-chirpy`, gem-based — currently resolves to 7.6).
- GitHub Pages **user site**: repo `knowledgemart/knowledgemart.github.io` → served at `https://knowledgemart.github.io/` (`url:` in `_config.yml` must stay that host). `github.username` and `social.links` in `_config.yml` only feed the sidebar icon and the author/copyright links, so they point at the author's personal profile (`klaudiawolinska`), not the `knowledgemart` org.

## Local preview — always via Docker

**Do not** try to `bundle install` natively. Run everything in a container (nothing gets installed on the host):

```bash
docker run --rm --name chirpy_preview \
  -v "$PWD":/workspace -w /workspace \
  -v chirpy_bundle:/usr/local/bundle \
  -p 4000:4000 -p 35729:35729 \
  mcr.microsoft.com/devcontainers/jekyll:2-bullseye \
  bash -lc "bundle install && bundle exec jekyll serve -H 0.0.0.0 -P 4000 --livereload"
```

- Serves at [http://localhost:4000](http://localhost:4000) (LiveReload on 35729). This is the image the repo's `.devcontainer` already declares.
- Gems are cached in the `chirpy_bundle` volume, so re-runs are fast. Stop with `docker stop chirpy_preview`.
- The container bind-mounts the repo, so `_site/` is written to the host (it is gitignored).
- `_config.yml` **changes require restarting the container** — Jekyll does not reload the config on regeneration. Content, assets and SCSS hot-reload fine.

## Deploy

Push to `main` → GitHub Actions (Chirpy "Build and Deploy") builds and publishes. Never commit `_site/` (gitignored). Commit/push only when the user asks.

## Conventions

- **Custom styles** go in `assets/css/jekyll-theme-chirpy.scss` (imports the theme, then appends overrides). Example already in place: `#sidebar .site-title` is capped to one line under the avatar.
- **Favicons** live in `assets/img/favicons/` (`favicon.ico`, `favicon.svg`, `favicon-96x96.png`, `apple-touch-icon.png`, `web-app-manifest-{192,512}.png`). They are generated from `assets/img/avatar.jpg` using `sips` **+** `python3` **only** (no ImageMagick on host or in the container): `sips` for the PNGs, plain `python3` to assemble the multi-size `.ico` and the raster-embedded `.svg`. `site.webmanifest` is generated by the theme from `site.title` — no manual edit needed.
- **Avatar**: `assets/img/avatar.jpg` (referenced by `avatar:` in `_config.yml`).
- **Sidebar mail icon** requires `social.email` in `_config.yml`. The theme toggle appears only when `theme_mode` is empty (default follows system); setting it to `light`/`dark` hides the toggle.
- Posts in `_posts/`, nav tabs in `_tabs/`, site config in `_config.yml`.

## Working style

- We iterate and verify **locally together** before committing.
- Do **not** take browser screenshots for visual confirmation — verify with DOM measurements (`preview_eval`/`preview_inspect`) when a check is needed; the user reviews visuals manually.
